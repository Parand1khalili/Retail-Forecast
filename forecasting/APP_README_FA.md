## وقتی صفحه «Python فعال: نامشخص» نشان می‌دهد

این پیام در نسخه‌های قبلی UI به معنی قطعی «CatBoost نصب نیست» نبود. ممکن است فایل HTML جدید توسط **سرور قدیمی که هنوز روی پورت 8765 در حال اجراست** سرو شده باشد، ولی آن سرور فیلد `runtime.dependencies` جدید را در پاسخ `/api/health` برنگرداند. حالت دیگر، ناموفق‌بودن درخواست `/api/health` است.

برای تشخیص دقیق در PowerShell:

~~~powershell
Invoke-RestMethod 'http://127.0.0.1:8765/api/health' | ConvertTo-Json -Depth 6
Get-NetTCPConnection -LocalPort 8765 -State Listen
~~~

اگر `runtime.dependencies` وجود ندارد، **سرور قدیمی/ناسازگار** در حال اجراست؛ نصب مجدد CatBoost را تکرار نکنید. در ترمینالی که نسخه قبلی `python app.py` اجرا شده با `Ctrl+C` آن را متوقف کنید. فقط اگر لازم بود مالک پورت را دقیق ببینید:

~~~powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen | ForEach-Object {
    Get-CimInstance Win32_Process -Filter "ProcessId=$($_.OwningProcess)" |
        Select-Object ProcessId, CommandLine
}
~~~

پس از تأیید اینکه پردازش واقعاً متعلق به همان اپلیکیشن است، آن را در ترمینال خودش ببندید. از حذف یا متوقف‌کردن پردازش ناشناس خودداری کنید. سپس در پوشه `forecasting` دستورهای زیر را اجرا کنید:

~~~powershell
python runtime_preflight.py
python app.py
~~~

در مرورگر آدرس `http://127.0.0.1:8765` را با `Ctrl+F5` نوسازی کنید. اگر API وضعیت قابل دریافت نباشد، UI جدید پیام اتصال و کد خطای آن را جداگانه نمایش می‌دهد؛ اگر `catboost` واقعاً نصب نباشد، مسیر Python و دستور نصب همان Interpreter را می‌دهد.

## رفع خطای CatBoost در VS Code و Windows

اگر سرور با `python app.py` اجرا می‌شود ولی موقع Forecast پیام `No module named 'catboost'` می‌دهد، معمولاً `py -3` و `python` به **دو Python متفاوت** اشاره می‌کنند. نصب موفق با `py -3 -m pip` الزاماً به محیط `python app.py` منتقل نمی‌شود.

1. سرور قبلی را در ترمینال VS Code با `Ctrl+C` متوقف کنید.
2. در پوشه `forecasting`، این دستورها را اجرا کنید:

~~~powershell
python -c "import sys; print(sys.executable)"
py -3 -c "import sys; print(sys.executable)"
python -m pip install -r requirements.txt
python runtime_preflight.py
python app.py
~~~

3. خروجی `runtime_preflight.py` باید `"ready": true` باشد. اگر `ready: false` دیدید، دستور `install_command` همان خروجی را **دقیقاً** در PowerShell اجرا و سرور را دوباره راه‌اندازی کنید. این دستور شامل مسیر Python فعال است و با فاصله‌های مسیرهای Windows نیز درست کار می‌کند.
4. صفحه `http://127.0.0.1:8765` را باز کنید. اگر Python مشکل داشته باشد، کادر قرمز رنگ وضعیت را قبل از اجرای Forecast نشان می‌دهد. بارگذاری و بررسی فایل Excel مستقل از CatBoost امکان‌پذیر است، اما Forecast، Model Lab و Export تا آماده‌شدن محیط غیرفعال می‌مانند.

برای اینکه لانچر `run_forecast.cmd` محیط Python سالم را انتخاب کند، آن را از **ریشه Repository** اجرا کنید. لانچر دیگر لزوماً اولین `.venv` را انتخاب نمی‌کند؛ قبل از بازکردن مرورگر، Import پکیج‌های موردنیاز را با همان Interpreter بررسی می‌کند. اگر هیچ محیط سالمی پیدا نشد، پنجره CMD بسته نمی‌شود و دستور نصب را نمایش می‌دهد.

**نکته‌ها:**
- دستور صحیح برای نصب، `python -m pip install -r requirements.txt` در *همان Interpreter برنامه* است، نه استفاده از pip یا Python دیگری.
- مسیر Python 3.14 کاربر ممکن است با مسیر `.venv\Scripts\python.exe` تفاوت داشته باشد. این اختلاف طبیعی است ولی باید نصب و اجرا با یک Interpreter انجام شوند.
- فایل‌های `.xlsx` باید در مرحله اول بارگذاری شوند؛ `.xlsb` مستقیماً پشتیبانی نمی‌شود.
- اگر پیام مربوط به پورت 8765 دریافت می‌کنید، نسخه قبلی برنامه یا سرور دیگری در حال اجراست؛ ابتدا برنامه فعال را بررسی کنید و بدون تأیید، پردازش دیگری را متوقف نکنید.

## آزمایش مدل‌ها از داخل رابط کاربری (Model Lab)

برای اجرای **Benchmark و Backtest** به ترمینال یا اسکریپت جداگانه نیازی نیست. در ویندوز می‌توان با دوبار کلیک روی فایل **\`run_forecast.cmd\`** در پوشه اصلی Repository، برنامه محلی را باز کرد. این فایل سرور را روی \`http://127.0.0.1:8765\` راه‌اندازی می‌کند. برنامه برای کار کردن باید روی همان رایانه در حال اجرا باشد.

1. در مرحله **۱** فایل Master با قالب \`.xlsx\` را Upload و Periodicity (ماهانه یا دوماهه) را مشخص کنید. برای فایل‌های دارای \`.xlsb\` ابتدا تبدیل معتبر به \`.xlsx\` لازم است.
2. در مرحله **۲** Mapping ستون‌های تشخیص‌داده‌شده را بررسی و تأیید کنید.
3. در مرحله **۳** یک سطح \`Market\` مثل \`All\` یا \`City\` را انتخاب کنید. اگر فایل چند سطح تجمیع واقعی مثل \`SKU\`/\`Product\` دارد، مقدار مناسب \`Element Caption\` را هم انتخاب کنید.
4. در مرحله **۴** از بخش **آزمایش مقایسه‌ای مدل‌ها (Model Lab)** گزینه «هر دو: حجم و ارزش فروش» یا یکی از این دو را برگزینید و روی **اجرای آزمون و مقایسه مدل‌ها** بزنید.
5. در مرحله **۵** جدول و نمودارهای مقایسه \`Legacy Global\`، \`Guarded Global\` و \`Hierarchical\` برای H1 تا H3 را مشاهده کنید. پایین صفحه شاخص، افق و سطح تحلیل را تغییر دهید تا عملکرد \`Subcategory\`، \`Brand\`، \`SKU\` و دیگر سطوح نمایش داده شود.
6. با **دانلود گزارش کامل (CSV / ZIP)** تمام گروه‌های ارزیابی‌شده را بگیرید. داخل ZIP برای هر شاخص، CSV خلاصه و در صورت وجود Holdout مستقل، CSV تمام گروه‌ها/سری‌ها قرار دارد. جدول صفحه فقط ۱۵ گروه بزرگ هر سطح را نشان می‌دهد.

**تفسیر:** WAPE برابر \`N/A\` به معنی نبود مخرج معتبر یا Holdout مستقل است، نه دقت ۱۰۰٪. کاهش خطای مثبت نسبت به \`Legacy Global\` نشان‌دهنده بهبود و مقدار منفی نشان‌دهنده افت است. نتیجه Holdout مستقل برای توضیح و مقایسه گزارش می‌شود و باعث تغییر خودکار Recipe انتخابی آینده بر اساس همان Holdout نمی‌شود. با کمتر از ۱۸ دوره تاریخی، Model Lab به‌جای عدد گمراه‌کننده پیام کمبود تاریخچه می‌دهد؛ با کمتر از ۳۰ دوره ممکن است گزارش انتخاب تاریخی وجود داشته باشد، ولی Holdout مستقل در دسترس نباشد.

**محدوده:** آزمون کل \`Market\` و سطح تجمیع انتخاب‌شده را شامل می‌شود، نه تنها SKU/Brand انتخاب‌شده برای پیش‌بینی عادی. داده Excel به‌صورت محلی خوانده می‌شود؛ فایل اصلی تغییر نمی‌کند. گزارش‌های موقت پس از ساخت ZIP پاک می‌شوند و ZIP آخرین ارزیابی فقط در حافظه سرور تا زمان ورود فایل جدید باقی می‌ماند. آزمون چند مدل در فایل‌های بزرگ زمان‌بر است و تا پایان پردازش، رابط مدت سپری‌شده را نمایش می‌دهد.

**برای Forecast عادی:** همچنان دکمه «محاسبه پیش‌بینی» را در همان مرحله چهارم بزنید؛ بخش مدل‌لب جایگزین آن نشده است.

# اجرای رابط پیش‌بینی RA

در این رایانه، فایل `run_forecast.cmd` را در پوشهٔ اصلی پروژه باز کنید. مرورگر روی `http://127.0.0.1:8765` باز می‌شود. برنامه فقط روی همین رایانه گوش می‌دهد و فایل به سرویس بیرونی فرستاده نمی‌شود. اگر فایل آمادهٔ نمونهٔ ماست روی این رایانه وجود داشته باشد، می‌توان آن را در مرحله ورود داده انتخاب کرد؛ در غیر این صورت فایل Excel کاربر بارگذاری می‌شود.

رابط با طراحی خنثی و فشرده، زمینه `#F6F7F9`، متن `#202630`، Navy اصلی `#355C7D`، Plum مکمل `#6C5B78` و کاربرد محدود Rose، Coral و Peach ارائه می‌شود. تمام رنگ‌ها و حالت‌های تعاملی از CSS Variable استفاده می‌کنند. گرادیان و کارت‌های تزئینی حذف شده‌اند؛ قلم فارسی از فونت‌های موجود روی رایانه به‌ترتیب Vazirmatn، IRANSansX، Noto Sans Arabic، Tahoma و Segoe UI استفاده می‌کند. فرایند در **پنج مرحله مستقل** انجام می‌شود: **۱) ورود فایل، ۲) تأیید ستون‌ها، ۳) انتخاب بازار و شاخص، ۴) انتخاب ماه و اجرای پیش‌بینی، ۵) مشاهده نمودارها و نتایج**. فقط مرحله فعال دیده می‌شود؛ پس از بارگذاری موفق فایل، دکمه «ادامه» فعال می‌شود. دکمه‌های «بازگشت» و نوار مراحل اجازه بازدید دوباره از مرحله‌های تکمیل‌شده را می‌دهند. اگر تشخیص ستون‌ها مبهم باشد، مرحله تأیید ستون‌ها برای اصلاح دستی الزامی می‌شود. حالت‌های «در حال پردازش»، «موفق» و «خطا» با پیام‌های مستقل نمایش داده می‌شوند و بعد از محاسبه موفق، صفحه نتایج باز می‌شود.

در مرحله چهارم خلاصه واقعی منبع داده، شاخص، فیلترها و ماه مقصد پیش از اجرا نشان داده می‌شود. پس از پیش‌بینی، مقدار ماه هدف و واحد آن اول نمایش داده می‌شوند؛ مقایسه با آخرین ماه فقط وقتی مقدار واقعی و مخرج معتبر وجود داشته باشد نشان داده می‌شود. نمودار خط پیوسته فروش واقعی را با Navy و خط‌چین پیش‌بینی را با Plum، محور زمان چپ‌به‌راست و Tooltip مقدار هر نقطه نشان می‌دهد. جزئیات Recipe و اعتبارسنجی در بخش بازشونده هستند. پیام‌های خطا شامل راهکارهای مشخص برای فایل نامعتبر، مسیر اشتباه یا قطع‌شدن سرویس می‌شوند. ویژگی یا درصد دقت ساختگی نمایش داده نمی‌شود.

## انتخاب تناوب و سطح مکانی

در مرحله ورود فایل، **ماهانه** یا **دوماهه** را قبل از بارگذاری انتخاب کنید. این گزینه هم در آپلود Drag & Drop و هم در خواندن مسیر محلی اعمال می‌شود. در حالت دوماهه، ستون‌هایی مانند `May-Jun 2026` به‌عنوان **یک دوره فروش** (با شناسه پایان دوره `2026-06`) وارد می‌شوند؛ `Year-*`، `MAT-*` و `YTD-*` صرفاً گزارش تجمیعی هستند و وارد سری زمانی نمی‌شوند. پیش‌بینی یک دوره پس از `May-Jun 2026` برابر `Jul-Aug 2026` است، نه دو پیش‌بینی ماهانه ساختگی. دوره‌های دوماهه باید به فاصله دو ماه و به‌صورت پیوسته باشند. برای آموزش و اعتبارسنجی، یک سال در داده دوماهه شش مشاهده دارد و محاسبات فصلی با همین تناوب سازگار شده‌اند. تغییر تناوب نیاز به خواندن مجدد فایل دارد و Cache آن از حالت ماهانه جداست.

اگر فایل شامل سطوحی مثل `All`، `City`، `Region` یا `OutletType` باشد، **همه ردیف‌ها حفظ می‌شوند** اما UI یک انتخاب مستقل و اجباری برای `Market` دارد. در هر درخواست فقط همان سطح مکانی وارد انتخاب مدل، اعتبارسنجی و محاسبه Forecast می‌شود؛ جمع‌زدن هم‌زمان `All` و `City` به دلیل هم‌پوشانی ممنوع است. سایر فیلترها مثل مکان، برند و SKU پس از انتخاب Market محدود می‌شوند. جدول WAPE نماینده همان سطح Market انتخاب‌شده است، نه همه سطح‌های هم‌پوشان. فایل قدیمی نمونه ماست همچنان در حالت ماهانه اجرا می‌شود.

برای فایل دارای `Volume Sales(Gr)`، واحد حجمی **گرم** شناخته می‌شود؛ تبدیل خودکار واحد یا تقسیم فروش دوماهه بین ماه‌ها انجام نمی‌شود.

در بخش داده، فایل مستر `.xlsx` را بارگذاری کنید یا مسیر آن را وارد کنید. برای فایل فعلی مسیر زیر قابل استفاده است:

`D:\Aug'26\Aug'26\Master Mast- Aug' 25.xlsx`

برای نمونهٔ درخواست‌شده، شهر `Tehran`، کمپانی و برند `Kalleh`، زیر‌برند `Seven` و ساب‌کتگوری اول `Stirred` را انتخاب کنید. در مستر، «سون» در ستون **SubBrand** با نام `Seven` ثبت شده است. شاخص را حجم یا مبلغ بگذارید. ماه مقصد فقط از ماه‌های **بعد از آخرین ماه موجود در فایل** انتخاب می‌شود؛ برای فایل فعلی سپتامبر، اکتبر و نوامبر ۲۰۲۶ است.

کاربر روش یا تعداد ماه آموزش را انتخاب نمی‌کند. سامانه چند نوع CatBoost، مدل قیمت و حجم، روش‌های آماری و ترکیب مدل‌ها را روی ماه‌های تکمیل‌شدهٔ همان فایل مقایسه می‌کند، روش مناسب هر شاخص و افق را انتخاب می‌کند و سپس با داده‌های در دسترس آموزش می‌بیند. نتیجهٔ آموزش و انتخاب ذخیره می‌شود تا درخواست‌های بعدی سریع‌تر باشند. در بخش «چرا این روش انتخاب شد؟»، نمودار WAPE روش‌های برتر، جدول کامل Candidateها و خطای Recipe منتخب در مبدأهای تاریخی نشان داده می‌شود. همه این اعداد از همان مقایسه‌ای استخراج می‌شوند که انتخاب مدل را تعیین کرده است؛ **مقیاس ارزیابی کل ترکیب‌های شهر × محصول در فایل است**، نه لزوماً همان فیلتر شهر/برند انتخاب‌شده در UI. تغییر فایل، شاخص یا افق، نمودارها را به‌روزرسانی می‌کند؛ تغییر فیلتر فقط پیش‌بینی جمع‌شده را تغییر می‌دهد، نه سیاست انتخاب سراسری. اگر تاریخچه کافی نباشد یا کنترل جهش قیمت مسیر معمول انتخاب را جایگزین کند، به‌جای نمودار مقایسه نامعتبر، علت عدم نمایش ذکر می‌شود. برای تاریخچه‌های کوتاه‌تر از ۱۸ ماه، برآورد پایه ارائه می‌شود و ادعای دقت تأییدشده نمایش داده نمی‌شود. دو یا سه ماه داده برای آموزش و سنجش یک مدل کامل کافی نیست.

سرتیترها و ترتیب ستون‌ها می‌توانند تغییر کنند: عنوان‌هایی مثل `Brand Name`، `Sub Brand`، `City Name`، `Location&Channel` و معادل‌های فارسی شناسایی می‌شوند. `Measure` یا `Index Name` مرز ستون‌هاست؛ **تمام ستون‌های دسته‌بندی قبل از آن**، از جمله عنوان‌های ناشناخته مثل `Element Description`، `SKUSize` و `SKUPackage`، در ساخت سری‌ها، فیلترهای UI و ویژگی‌های دسته‌ای CatBoost حفظ می‌شوند. ستون‌های معتبر **ماهانه بعد از این مرز** به‌عنوان تاریخچه خوانده می‌شوند؛ ستون‌های تجمیعی سالانه مانند `Year-2022` به‌اشتباه ماه تلقی نمی‌شوند. ماه باید شکل قابل تشخیصی مثل `Aug' 2026` یا `2026-08` داشته باشد و سرتیتر می‌تواند در ده ردیف اول قرار بگیرد.

بعد از خواندن، فهرست ستون‌های دسته‌بندی تشخیص‌داده‌شده و تعداد ماه‌ها در UI نمایش داده می‌شود. دکمه **«اصلاح دستی ستون‌ها»** اجازه می‌دهد مرز Measure، نگاشت City/Brand و دیگر فیلدها، انتخاب یا حذف دسته‌های اختیاری، و نام/واحد شاخص‌های حجم و مبلغ را دستی مشخص کنید. City و Brand برای ساخت سری‌های قابل مقایسه الزامی‌اند. اگر تشخیص اولیه ناموفق باشد، همین فرم خودکار باز می‌شود. فایل را می‌توان با انتخاب یا Drag & Drop بارگذاری کرد. برای نمونه بدون دادهٔ آماده نیز برنامه باز می‌شود و امکان بارگذاری فراهم است.

ساختار پشتیبانی‌شده همچنان مستر فروش **ماهانه** با ردیف‌های جداگانهٔ حجم و مبلغ است؛ هر فایل دلخواه یا فایل فاقد ماه‌های پیوسته لزوماً قابل پردازش نیست. اگر ستون `Market` وجود داشته باشد، همه سطوح فایل به شکل مستقل ذخیره می‌شوند؛ هر درخواست پیش‌بینی فقط روی یک سطح انتخاب‌شده اجرا می‌شود.

واحدها از نام شاخص یا نگاشت شما گرفته می‌شوند: مثلاً حجم شیر می‌تواند لیتر و مبلغ تومان باشد. تبدیل واحد یا ارز حدس زده نمی‌شود. شیت‌های ماهانهٔ همپوشان به ترتیب تاریخ ترکیب می‌شوند و شیت جدیدتر برای ماه مشترک اولویت دارد. اگر سلول ماهانه ناقص باشد، فایل برای بررسی برگردانده می‌شود.

آزمون جدید مدل‌های خودکار در `outputs/automatic_models/` ذخیره می‌شود. هدف دقت ۹۰٪ در این پروژه به معنای WAPE حداکثر ۱۰٪ است؛ این معیار میانگین وزنی خطای مجموعهٔ ترکیب‌های شهر/محصول است و دقت ۹۰٪ برای تک‌تک کالاها یا ماه‌های آینده را تضمین نمی‌کند. آزمون قبلیِ طول تاریخچه و محدودیت‌های داده در `outputs/yoghurt_history_study/REPORT_FA.md` باقی مانده است.

## ارزیابی مستقل Forecast در برابر Actual واقعی

اگر خروجی `retail_forecast_full.xlsx` شامل Sheetهای `Volume` و `Value` است، شیت سوم را به **مستر اصلی فروش Actual با ستون Measure** و دوره هدف، مثلاً `Jul-Aug 2026`، اختصاص بدهید. برای کنترل بدون دستکاری فایل ورودی:

```powershell
python forecasting/evaluate_actuals.py "retail_forecast_full.xlsx" --output "outputs/forecast_validation"
```

خروجی‌های محلی: `reconciliation.json` برای تطبیق کلید ردیف‌ها و مقادیر تاریخی؛ `scorecard.csv` برای WAPE، Bias، MAE و RMSE تفکیک‌شده بر اساس Market Level؛ `row_errors.csv` برای ردیف‌ها؛ `baseline.csv` برای مقایسه Last Period و Seasonal Naive؛ `market_shares.csv` و `mat_shares.csv` برای سهم حجمی/ریالی در سطح دسته، برند، شهر، اندازه و بسته‌بندی؛ `time_series.csv` و `demand_segments.csv` برای تاریخچه و فروش‌های پراکنده.

**تعاریف:** WAPE بر اساس جمع خطای مطلق در سطح سری و Bias بر اساس تفاوت مجموع پیش‌بینی و Actual است. `MAT` برای فایل دوماهه شش دوره متوالی و برای فایل ماهانه دوازده دوره است. هر `Market` مستقل ارزیابی می‌شود؛ جمع `All` و `City` باعث دوباره‌شماری می‌شود. برای فروش واقعی صفر، APE ردیفی تعریف نشده؛ این ابزار از ساخت صفر مصنوعی پرهیز می‌کند.

**هشدار امنیت داده:** فایل‌های اصلی، خروجی‌های ارزیابی، CSVهای ردیف محصول و گزارش‌های حاوی داده Retail Audit خصوصی هستند و نباید در Git Commit شوند. فقط کد عمومی و تست‌های مصنوعی در Git نگهداری شوند. این ابزار ارزیابی یک دوره Actual است؛ جایگزین Rolling Backtest چنددوره‌ای نیست.
